# 1.2.0 升级说明（城镇与建筑组件化）

| 项 | 内容 |
|---|---|
| 基线版本 | 1.1.4 |
| 目标版本 | **1.2.0** |
| 状态 | 待确认 |
| 主题 | 城镇面板与建筑资源组件化 + 母港初始建筑 + 商品供应机制 |

## 1. 为什么要做这件事

当前问题：

- 母港与岛屿各自实现面板，逻辑重复、体验割裂
- 建筑写死在代码里（等级、花费、效果散落在 base_scene 与 GameState）
- 未来接入美术资源（城镇背景、建筑立绘、点击热点）时，**代码与资源会缠在一起，难以拆分**

目标：**数据与表现分离**。建筑、城镇布局、面板构成全部变成可替换的资源，
美术资源只需填字段，不改代码。

## 2. 三个公共组件

### 2.1 TownPanel（城镇面板构建器）

| 项 | 内容 |
|---|---|
| 文件 | scripts/ui/town_panel.gd |
| 职责 | 根据港口 id 与等级，生成菜单项与对应面板 |
| 输入 | port_id、tier、is_home |
| 输出 | 菜单按钮列表 + 面板实例 |
| 复用 | 母港与所有岛屿共用同一套 |

**菜单项由数据驱动**，不再写死在场景脚本里：

    菜单项 = 该城镇等级可用的建筑 + 通用功能（市场/任务/酒馆等）

### 2.2 BuildingDef（建筑定义，扩展）

现有字段：id、display_name、effect_text、cost（gold/timber/iron/weeks）、max_level、production。

**新增字段**

| 字段 | 类型 | 用途 |
|---|---|---|
| category | String | 民生 / 生产 / 服务 / 军事 |
| unlock_tier | int | 城镇达到几级才出现 |
| sort_order | int | 菜单与布局排序 |
| icon_path | String | 图标资源（空则用文字占位） |
| scene_path | String | 建筑立绘/场景资源（空则用表格行占位） |
| slot_id | String | 对应 TownLayout 中的槽位 |
| is_initial | bool | 是否开局自带（母港仅总督府与仓库为 true） |

**示例（船坞）**

    id = &"drydock"
    display_name = "船坞"
    category = "生产"
    unlock_tier = 1
    sort_order = 20
    icon_path = ""            # 美术待补
    scene_path = ""           # 美术待补
    slot_id = "slot_drydock"
    is_initial = false

### 2.3 TownLayout（城镇布局资源）

| 项 | 内容 |
|---|---|
| 文件 | data/towns/layout_<tier>.tres |
| 职责 | 描述城镇界面的槽位坐标与背景 |

| 字段 | 类型 | 用途 |
|---|---|---|
| tier | int | 对应城镇等级 |
| background_path | String | 城镇背景图（空则纯色底） |
| slots | Array | 槽位列表：{id, position, size} |
| menu_side | String | 菜单在左还是在下 |

## 3. 渲染策略（关键）

| 资源状态 | 渲染方式 |
|---|---|
| scene_path 为空 | 用现有表格行占位，功能完整 |
| scene_path 有值 | 实例化场景，绑定点击热点 |
| icon_path 为空 | 用文字名称 |
| background_path 为空 | 纯色底 |

> **美术接入流程**：只改 .tres 的路径字段，代码零改动。
> 这是本版存在的核心理由——不做这层抽象，后续美术替换必然返工。

## 4. 母港初始建筑

| 城镇 | 初始建筑 | 说明 |
|---|---|---|
| 母港（翡翠港村） | **总督府 + 仓库** | 其余全部需要玩家建造 |
| 其他岛屿 | 按等级给全套 | 港村 3 座、港镇 5 座、港城全部 |

**解锁规则**

| 建筑 | 解锁等级 |
|---|---|
| 酒馆 / 织帆坊 / 瞭望塔 | 港村 |
| 船坞 / 铸造厂 | 港镇 |
| 交易所 / 总督府升级 | 港城 |

## 5. 商品供应机制

| 类型 | 规则 |
|---|---|
| 本岛特产 | 固定有货，满值 80%，回归快（每周 +3%） |
| 非特产普通品 | 低概率出现（每周 20%），初始 20%~40% |
| 军用品 | 仅在有「铸造厂」的港口出售 |
| 贵金属 | 仅港城出售，数量少（满值 10%） |

**目的**：让「跑商」有理由——不同港口货架不同，才有路线可跑。

## 6. 验收标准

| # | 验收点 |
|---|---|
| 1 | 母港与岛屿使用同一个 TownPanel 构建器 |
| 2 | 岛屿城镇界面与母港完全同构（菜单项一致、面板一致） |
| 3 | 建筑全部来自 BuildingDef 资源，代码中无写死的建筑表 |
| 4 | 建筑新增 category / unlock_tier / sort_order / icon_path / scene_path / slot_id / is_initial 字段 |
| 5 | 存在 3 份 TownLayout 资源（港村/港镇/港城） |
| 6 | scene_path 为空时用表格行占位且功能完整 |
| 7 | scene_path 有值时实例化场景（用一张占位图验证） |
| 8 | 母港开局只有总督府与仓库，其余需建造 |
| 9 | 其他岛屿按等级自带全套建筑 |
| 10 | 特产固定供应、非特产低概率出现 |
| 11 | 军用品只在有铸造厂的港口出现 |
| 12 | 全部新建状态进存档，旧档可读 |
