# 0.13.0-alpha 升级说明

| 项 | 内容 |
|---|---|
| 基线版本 | 0.12.0-alpha |
| 目标版本 | 0.13.0-alpha |
| 状态 | 待确认 |
| 主题 | 贷款体系重构：多笔并发 + 金额分级 + 期限分级 |

> **阶段定调**：到 1.0.0 正式版之前，本阶段只做**经济系统**。
> 除需求方另行指定外，不再编写其他系统（战斗、阵营、美术）的文档与开发。

## 1. 背景

0.12 的贷款是**单笔**的：借了就锁死，还清才能再借。这带来两个问题：

- 玩家手里有 10 万存款，却只能借 1 万——额度利用率低
- 想短借周转与长借扩张不能并存

本版改为**多笔并发**，并用**金额分级 + 期限分级**把复杂度关进笼子。

## 2. 贷款金额分级（5 级）

| 等级 | 单笔额度 | 定位 |
|---|---|---|
| L1 | **1,000** | 应急周转（修船、补给） |
| L2 | **5,000** | 小额进货 |
| L3 | **20,000** | 中型贸易 / 拍卖小额 |
| L4 | **50,000** | 大型贸易 / 整船拍卖 |
| L5 | **100,000** | 重资产扩张 |

金额固定为整档，**玩家不能自由填数字**——降低输入复杂度，也让风控规则可预期。

## 3. 期限分级（按金额档）

| 金额档 | 可选期限 | 周利率 |
|---|---|---|
| L1 1,000 | 一季（12 周）/ 半年（26 周） | 0.2% / 0.3% |
| L2 5,000 | 一季（12 周）/ 半年（26 周）/ 一年（52 周） | 0.2% / 0.3% / 0.5% |
| L3 20,000 | 半年（26 周）/ 一年（52 周） | 0.3% / 0.5% |
| L4 50,000 | 仅一年（52 周） | 0.5% |
| L5 100,000 | 仅一年（52 周） | 0.5% |

**设计逻辑**

- 小额允许短借：周转快，利息负担小
- 大额强制长期：银行不接受大额短期套利（借大钱三周就还）

**利息示例**

| 金额档 | 期限 | 利息 | 到期还本息 |
|---|---|---|---|
| L1 1,000 | 一季 | 24 | 1,024 |
| L2 5,000 | 半年 | 390 | 5,390 |
| L3 20,000 | 一年 | 5,200 | 25,200 |
| L4 50,000 | 一年 | 13,000 | 63,000 |
| L5 100,000 | 一年 | 26,000 | 126,000 |

## 4. 多笔并发与额度约束

### 4.1 借贷前提

| 项 | 规则 |
|---|---|
| 前提 1 | 在该银行**有存款** |
| 前提 2 | **本息总额不超过存款总额** |
| 前提 3 | 未还贷款笔数 ≤ **6 笔**（UI 与账务的简化上限） |

**本息总额定义**

    本息总额 = Σ(每笔未还贷款的本金 + 该笔剩余未付利息)

新借款必须满足：`本息总额 + 新贷款(本金+利息) ≤ 存款总额`

### 4.2 示例

    存款 100,000
    已借：L3 20,000（一年期，利息 5,200）→ 本息 25,200
    再借：L4 50,000（一年期，利息 13,000）→ 本息 63,000
    合计 88,200 ≤ 100,000  →  允许

    若再想借 L5 100,000（本息 126,000）→ 合计 214,200 > 100,000  →  拒绝

### 4.3 每笔独立结算

每笔贷款有**独立的期限、利率、剩余周数、已付利息**：

    贷款 A：L3 20,000 · 一年 · 0.5%/周 · 剩 40 周
    贷款 B：L1 1,000  · 一季 · 0.2%/周 · 剩 5 周

两者到期时间、月付息额都分开计算，互不影响。

## 5. 计算压力评估

| 项 | 规模 | 结论 |
|---|---|---|
| 单笔数据结构 | 约 8 个字段 | — |
| 并发上限 | 6 笔 | 共约 48 个数值 |
| 每周结算 | 遍历 6 笔，各做 1 次乘加 | **6 次运算/周**，忽略不计 |
| 借款时额度校验 | 遍历 6 笔求和 | **6 次运算/次** |
| UI 渲染 | 6 行 | 与现有面板同量级 |

> **结论：算力不是问题**。复杂度只体现在**账务正确性**（每笔独立期限），
> 而这属于逻辑复杂度，不是性能复杂度。用 6 笔上限 + 金额分级把状态空间压到可控。

## 6. 还清方式

| 方式 | 说明 |
|---|---|
| 单笔提前还清 | 按该笔已过周数与原利率结算利息 |
| 全部还清 | 一次性结清所有未还贷款 |
| 到期自动 | 到期当周自动还本息，资金不足则破产 |

## 7. 破产判定（沿用 0.12 后果）

任一贷款在**付息日或到期日**资金不足 → 触发破产：

| 项 | 结果 |
|---|---|
| 存款与现金 | 全部清零 |
| 海军声望 | 归零 |
| 通缉度 | +60 |
| 所有贷款 | 清空 |
| 船与装备 | 保留 |

## 8. 验收标准

| # | 验收点 |
|---|---|
| 1 | 贷款分 5 档，金额固定为 1000 / 5000 / 20000 / 50000 / 100000 |
| 2 | 各档可选期限符合分级表（L4/L5 只能借一年） |
| 3 | 可同时持有最多 6 笔贷款 |
| 4 | 新借款校验：本息总额 ≤ 存款总额 |
| 5 | 每笔贷款的期限、利率、剩余周数独立结算 |
| 6 | 支持单笔提前还清与全部还清 |
| 7 | 任一笔付息或到期资金不足 → 破产（四项后果） |
| 8 | 超过 6 笔时拒绝新增并提示 |
| 9 | 所有贷款进存档，读档后剩余周数与已付利息一致 |

## 9. 不做

- 不做浮动利率
- 不做玩家自定义金额
- 不做企业/商号账户
