# 世界地图系统改造评估（参考 Godot 4.6 架空海洋世界地图设计文档）

| 项 | 内容 |
|---|---|
| 评估日期 | 2026-11-23 |
| 参考文档 | `Godot_4.6_架空海洋世界地图系统设计文档.md` |
| 当前实现 | 30 张海图，节点 + 邻接表 + 只读世界地图面板 |
| 结论 | **可行，但不建议整包照搬**；分三档改造，先做低风险交互增强 |

## 1. 参考文档的核心架构

| 层 | 内容 |
|---|---|
| 美术表现层 | 世界地图背景图、装饰、光影 |
| 区域几何层 | Tiled 绘制的不规则 Polygon + 区域属性 |
| 导航逻辑层 | 有向 Transition 图 + 构建/校验工具 + Dijkstra |
| 游戏运行层 | Area2D 命中、Polygon2D 填充、出口触发器、场景切换 |

关键决策：**几何相邻 ≠ 可通行**，通行必须由 Transition 显式授权；地图点击不等于无条件传送。

## 2. 可提取的开发设施

| # | 设施 | 文档位置 | 当前状态 | 复用度 |
|---|---|---|---|---|
| 1 | 有向 Transition 图 | §7.3 / §9.3 | 已有无向邻接 + 航门校验 | 高（改为有向即可） |
| 2 | 航门 → 切换协议 | §9.5 / §10 | 已实现（靠近航门按 E 切图） | **很高，可直接复用** |
| 3 | 出生点（entry_spawn_id） | §9.5 | 未实现，当前固定出生 | 中（1 轮内可加） |
| 4 | 多边形区域 + 悬停/选中 | §5.3 / §9.2 | 无，当前是圆点 | 高价值 |
| 5 | 状态模型（hover/selected/current/reachable/locked） | §5.3 | 仅 current/explored | 高价值 |
| 6 | Dijkstra 路径与路线展示 | §8.3 / §9.4 | 无 | 中（世界地图只读，可做路线预览） |
| 7 | Tiled + Python 流水线 + 校验 | §6 / §11 / §12 | 无 | 低（依赖美术底图与 Tiled 工作流） |
| 8 | Agent 地图生产接口（staging/revision） | §11 | 无 | 低（当前单人开发，收益小） |

## 3. 当前实现与文档的差距

| 差距 | 说明 | 影响 |
|---|---|---|
| 无美术底图 | 文档要求 4096×2304 世界地图背景；当前无美术资源 | **最大阻塞**，1.6 才接美术 |
| 无多边形区域 | 当前 30 个圆点 + 归一化坐标 | 观感与「地图」差距大 |
| 无悬停/选中 | 面板只读、不响应点击 | 信息展示弱 |
| 无路线/寻路 | 无 Dijkstra，无路线高亮 | 无法回答「怎么去」 |
| 无 Tiled 流程 | 当前数据直接写在 .tres | 大规模编辑成本高 |
| 场景切换协议 | 已有航门 + 邻接校验，但无出生点 | 可小幅补齐 |

## 4. 改造方案与成本

### 方案 A：交互增强版（推荐先做）

保留节点图，升级交互与信息展示：

| 项 | 内容 |
|---|---|
| 新增 | 悬停高亮、点击选中、右侧详情（名称/势力/等级/危险度/相邻）、可达高亮 |
| 新增 | 拖拽平移 + 滚轮缩放（Camera2D 或画布变换） |
| 新增 | 从当前海域到选中海域的**只读路线预览**（Dijkstra） |
| 不改 | 数据结构、通行规则、场景切换 |
| 成本 | **1.5 轮** |
| 风险 | 低；无美术依赖 |

### 方案 B：多边形世界地图（美术接入后）

| 项 | 内容 |
|---|---|
| 新增 | `RegionDef`（polygon/anchor/scene/gate）、背景图路径 |
| 新增 | Node2D + Polygon2D + Area2D 命中 + Camera2D |
| 新增 | 纯 Python 校验/构建脚本（不强制 Tiled） |
| 复用 | 现有邻接表升级为有向 Transition；航门协议不变 |
| 成本 | **3 轮**（含占位底图） |
| 依赖 | 世界地图底图（可用程序生成占位） |

### 方案 C：完整文档落地

| 项 | 内容 |
|---|---|
| 新增 | Tiled 源 + Python pipeline + 校验 + Agent 工具 + 100 区域 + 出生点协议 + 动画航线 |
| 成本 | **6~8 轮**，并强依赖美术与 Tiled 工作流 |
| 适合 | 世界扩展到 100 区域、需要策划独立编辑地图时 |

## 5. 推荐路径

| 阶段 | 方案 | 时机 |
|---|---|---|
| 1.5.x | A：交互增强（悬停/选中/详情/缩放/路线预览） | **现在** |
| 1.6 | B：接美术底图时改多边形区域 | 美术资源就绪后 |
| 2.x | C：仅当区域规模到 ~100 再上 Tiled/pipeline | 远期 |

## 6. 结论

| 问题 | 结论 |
|---|---|
| 能否基于文档改造 | **能**，移动/交互/图论部分可直接借鉴 |
| 是否应整包照搬 | **不建议**：100 区域 + Tiled + Agent 工具对当前 30 图规模过重 |
| 当前最大短板 | 无美术底图、无交互、无路线预览 |
| 建议 | 先做方案 A（1.5 轮），用最小成本补齐观感与逻辑 |
