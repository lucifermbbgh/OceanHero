## 1. 背景

0.13 让价格会动了，但玩家仍然**看不出该不该买**：

- 只有一个瞬时价格和涨跌箭头，看不出趋势
- 不知道买多少才算划算（买了会不会砸手里）
- 商品之间的联动（朗姆酒涨了，香料会怎样）还没有

本版把「该不该做这笔交易」变成界面上可以直接读到的结论。

## 2. 需求

### 2.2 边际利润提示（E3 · 含货舱余量）

**算法**

    可用容量 = 货舱上限 − 当前载货
    可买数量 = min(可用容量 / 单位体积, 该港库存)
    对每件：MP = 目标港卖价 − 本港买价
    累计到 MP ≤ 0 或达到可买数量

**展示（世界市场每行末尾）**

| 情况 | 显示 |
|---|---|
| 全程为正 | `还能吃进 N 件`（绿） |
| 中途转负 | `再买 M 件后不划算`（黄） |
| 一开始就负 | `不划算`（红） |
| 容量为 0 | `货舱已满`（灰） |

### 2.3 交叉弹性（E4）

| 木材 | 铁矿 | 互补（都要建房） | 0.2 |

### 2.3.1 传导阈值的作用

> 阈值决定「涨跌多大幅度才值得传导给关联商品」。

**机制（每周只跑一次，不级联）**

    第 1 步：看本周某商品的涨跌幅 |Δ%|
    第 2 步：若 |Δ%| < 阈值 → 不传导，关联商品不受影响
    第 3 步：若 |Δ%| ≥ 阈值 → 传导值 = Δ% × 交叉系数（上限 ±8%）
    第 4 步：传导值并入关联商品的漂移目标，再经 25% 回归与 ±15% 上限

**算例**（阈值 5%，朗姆酒 ↔ 香料 互补系数 0.4）

| 本周朗姆酒涨跌 | 是否传导 | 香料受影响的漂移目标 |
|---|---|---|
| +3% | ❌ 不传导 | 不变 |
| +5% | ✅ 触发 | +2.0%（需求上升 → 价格上涨） |
| +8% | ✅ 触发 | +3.2% |
| −10% | ✅ 触发 | −4.0% |

**为什么阈值不能太低或太高**

| 阈值 | 效果 | 代价 |
|---|---|---|
| **低**（如 2%） | 几乎每周都传导 → 商品价格**明显联动**，世界看起来很活 | 价格噪声变大，玩家难以判断涨跌是"自己的库存"还是"被别人带动的" |
| **5%（当前）** | 只有较明显的波动才传导，联动可感知但不嘈杂 | 关系表使用频率中等 |
| **高**（如 10%） | 很少触发 → 各商品**基本独立** | 交叉弹性形同虚设，设计的关系等于没用 |

**为什么不做级联传导**

若 A 影响 B、B 又影响 C，多轮传导会形成反馈回路，价格容易震荡失控。
本版只做**单层传导**：A → B 之后，B 的这次变化不再传给 C。

**参数位置**：`balance_config.tres` 的 `cross_threshold`（默认 0.05）。
