# 版本开发文档

> 本文件是**版本迭代的唯一权威记录**。
> 规则：**先写升级文档 → 确认内容 → 再开发 → 测试 → 归档**，不允许先写代码后补文档。

## 1. 版本号规则

```
主版本.次版本.修订号-阶段
  0   .  7   .  0    -alpha
```

| 位 | 何时 +1 | 例子 |
|---|---|---|
| 主版本 | 玩法闭环发生根本变化 / 正式发行 | 0 → 1 |
| 次版本 | 一个完整的**功能批次**（设计+开发+测试+文档） | 0.7 → 0.8 |
| 修订号 | 不改变玩法的修复与打磨 | 0.7.0 → 0.7.1 |
| 阶段 | `alpha` 内部试玩 / `beta` 对外测试 / 无 正式版 | — |

**每次次版本必须有一份独立的升级说明，放在 `docs/版本文档/` 下：`X.Y.Z-升级说明.md`。**

## 0.9 协作约定：单轮开发容量评估（2026-11-18 起）

> 为避免「设计完 → 开发一半 → 中断 → 重新拆分」的循环，
> **每份升级说明在开发前必须包含容量评估与拆分方案**。

### 9.1 容量基准

| 项 | 经验值 |
|---|---|
| 单轮可完成 | 约 3~5 个模块改动 + 20~40 条测试断言 |
| 触及范围 | 新增/修改 300~600 行，涉及不超过 3 个既有系统 |
| 超出则拆分 | 必须拆成补丁号连续交付（1.2.2 / 1.2.3 / 1.2.4） |

### 9.2 升级说明必须回答

| 问题 | 写在哪 |
|---|---|
| 本次范围能否一轮做完 | 文档「开发评估」小节 |
| 若不能，拆几个补丁、每个补丁做什么 | 同上，列成表格 |
| 哪些项依赖后续版本 | 「依赖」小节 |

### 9.3 细化到「单一功能点」

> 一个补丁 = 一个功能点。功能点过大时继续拆，宁可版本号多，不要单版塞多个模块。

| 维度 | 单一功能点上限 |
|---|---|
| 涉及系统 | ≤ 2 个 |
| 涉及文件 | ≤ 3 个 |
| 代码量 | ≤ 150 行（不含测试） |
| 测试断言 | 5 ~ 15 条 |
| 完成判据 | 一条用户可感知的行为变化 |

**允许批量交付**：一轮内可连续做完 2~3 个**互不依赖**的功能点，
但每个功能点仍各自占一个补丁号、各自一份说明、各自一次提交。

### 9.4.1 数据管理策略：暂不使用数据库（2026-11-18 决定）

| 项 | 内容 |
|---|---|
| 当前静态数据规模 | 约 150 项（商品 28 / 建筑 8 / 海图 9 / 船只 ~30 / 装备 ~40） |
| 决策 | **暂不引入 SQLite**，继续用 Resource + 校验层 |
| 复查触发条件 | 静态数据 > 800 项，或需要 Mod / 多人 |
| 届时的替代路径 | 先 CSV 单一数据源 + 生成器；仍不够再评估 SQLite |

**评估要点**

| 维度 | 判断 |
|---|---|
| 约束能力（分类合法/引用完整） | 用校验函数即可获得，无需 DB |
| 查询能力 | 启动建索引字典，比 SQLite I/O 更快 |
| 批量编辑与 diff | 规模上去后改用 CSV 单一源，而非 DB |
| DB 的独有优势 | 外部可编辑（Mod）、事务并发（多人）、分析型查询 |
| DB 的代价 | 跨平台二进制、schema 迁移、编辑器工作流断裂 |

**扩容路线**

| 阶段 | 数据量 | 做法 |
|---|---|---|
| 现在 | ~150 | Resource + validate_defs() 校验 |
| 300+ | 中 | data/defs/*.csv 为唯一源，生成器产出资源 |
| 800+ 或 Mod | 大 | 再评估 SQLite（构建期用，运行时读内存） |

### 9.5 拆分原则

| 原则 | 说明 |
|---|---|
| 按模块边界切 | 一个补丁只动 1~2 个系统 |
| 每个补丁可独立验收 | 不做「必须配合下一个补丁才能跑」的半成品 |
| 先基础设施后表现层 | 例如先做动态港口，再做菜单差异 |
| 版本号连续 | 不跳号，不合并到下一个次版本 |

## 1.0 补丁版本规则

| 情况 | 做法 |
|---|---|
| 次版本的功能没做完 | **不进下一版本**，改用补丁号继续：0.10.0 未完成 → **0.10.1** 继续完善 |
| 补丁只做同类工作的收尾 | 不新增主题，只补齐 0.10.0 验收清单里未通过的项目 |
| 补丁也要写升级说明 | `0.10.1-升级说明.md`，内容 = 未完成项清单 + 原因 |

## 3. 下一版本：0.14.0-alpha（待确认）

> 目标：让「三级岛屿」真正有功能差异，并把母港做成成长线。

### 3.1 需求清单

| # | 需求 | 说明 |
|---|---|---|
| 1 | **港口服务按等级开放** | 村庄：维修/市场/任务/换船；乡镇：+船厂+酒馆；城市：+交易所+声望 |
| 2 | **母港成长线** | 渔港村落 → 乡镇（5,000 金 + 100 木 + 50 铁）→ 港口城市（30,000 金 + 400 木 + 200 铁）；升级后解锁对应面板 |
| 3 | **岛屿港口 UI 统一** | 岛屿港口与母港共用面板组件，避免两套 UI 逻辑 |
| 4 | **特产价格差异化** | 不同等级港口特产价格不同（大港便宜、小港贵），形成贸易路线 |

### 3.2 验收标准

- 村庄级港口看不到「船厂」「酒馆」入口
- 母港升级到乡镇后，船厂与基地建设面板出现在母港
- 母港升级到城市后，交易所与声望面板出现
- 同一特产在城/镇/村三个港口价格呈梯度（差异 ≥ 15%）

### 3.3 不做

- 不做 Boss 技能
- 不做美术资源替换（走独立排期）
- 不做多存档界面重构

| 设计确认 | 0.2 轮 |
| 开发 | 1.2 轮 |
| 测试与文档 | 0.6 轮 |

## 5. 未来：外交模块（不细化，仅登记）

> 海军从「单一势力」拆分为 **6 个国家**，各自独立声望与外交关系。
> 私掠许可证绑定具体国家：持 A 国私掠证劫掠 B 国商船合法，劫掠 A 国视为叛国。

| 国家 | 定位 | 特征 |
|---|---|---|
| **澜国** | 海军强国 | 舰船火力与装甲最硬，声望门槛最高 |
| **赤鳞** | 商会联邦 | 贸易与市场最发达，收购价最好 |
| **霜屿** | 北方岛国 | 耐寒船体，船员耐久高，航线偏北 |
| **玄礁** | 海盗诸岛 | 松散联盟，黑市最繁荣，通缉风险最低 |
| **白鲸** | 渔业邦联 | 谷物与木材产出高，物价低廉 |
| **苍梧** | 新兴王国 | 均衡，崛起中，对各阵营都开放 |
