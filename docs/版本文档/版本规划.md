# 版本开发文档

> 本文件是**版本迭代的唯一权威记录**。
> 规则：**先写升级文档 → 确认内容 → 再开发 → 测试 → 归档**，不允许先写代码后补文档。

## 1. 版本号规则

```
主版本.次版本.修订号-阶段
  0   .  7   .  0    -alpha
```

| 位 | 何时 +1 | 例子 |
|---|---|---|
| 主版本 | 玩法闭环发生根本变化 / 正式发行 | 0 → 1 |
| 次版本 | 一个完整的**功能批次**（设计+开发+测试+文档） | 0.7 → 0.8 |
| 修订号 | 不改变玩法的修复与打磨 | 0.7.0 → 0.7.1 |
| 阶段 | `alpha` 内部试玩 / `beta` 对外测试 / 无 正式版 | — |

**每次次版本必须有一份独立的升级说明，放在 `docs/版本文档/` 下：`X.Y.Z-升级说明.md`。**

## 0.1 术语定义（2026-11-18 确认）

> 版本号格式 `主版本号.特性版本号.小版本号`，例如 **1.3.2**。

| 称呼 | 对应位 | 变化示例 | 含义 |
|---|---|---|---|
| **主版本号** | 第 1 位 | 1.x → 2.x | 整体系统的大规模迭代 |
| **特性版本号** | 第 2 位 | 1.2 → 1.3 | 系统模块的开发更新 |
| **小版本号** | 第 3 位 | 1.3.2 → 1.3.3 | 功能点的开发更新 |

**当前所处位置**

| 项 | 值 |
|---|---|
| 主版本 | **1.x** |
| 特性版本 | **1.3**（多国割据与海域战争） |
| 当前小版本 | **1.4.3** |

**使用规则**

| 规则 | 说明 |
|---|---|
| 说「主版本」时 | 指 1.x 整条线，或 2.0 这类跨主版本 |
| 说「特性版本」时 | 指 1.3 这样的一批模块功能 |
| 说「小版本」时 | 指 1.3.2 这样的单一功能点 |
| 文档命名 | 特性版本规划用 `X.Y-系列规划.md`；小版本用 `X.Y.Z-升级说明.md` |

## 0.2 美术资源排期

> 美术不单独占用版本号，作为**并行工作流**在每个特性版本中逐步交付。

| 特性版本 | 美术交付 | 依赖 |
|---|---|---|
| 1.3 | 城镇建筑占位图规格定稿、港口背景草图 | 1.2 的 scene_path 与槽位 |

| 1.7 | 世界地图插图（31 张海图位置与国色） | 1.3 邻接图 |

**原则**

| 原则 | 说明 |
|---|---|
| 代码先行 | 资源未到位时使用纯色占位，功能不受阻 |
| 按界面优先级 | 玩家停留越久的界面越早做 |
| 不阻塞开发 | 美术未交付不阻塞小版本发布 |

## 1.0 补丁版本规则

| 情况 | 做法 |
|---|---|
| 次版本的功能没做完 | **不进下一版本**，改用补丁号继续：0.10.0 未完成 → **0.10.1** 继续完善 |
| 补丁只做同类工作的收尾 | 不新增主题，只补齐 0.10.0 验收清单里未通过的项目 |
| 补丁也要写升级说明 | `0.10.1-升级说明.md`，内容 = 未完成项清单 + 原因 |

## 3. 下一版本：0.14.0-alpha（待确认）

> 目标：让「三级岛屿」真正有功能差异，并把母港做成成长线。

### 3.1 需求清单

| # | 需求 | 说明 |
|---|---|---|
| 1 | **港口服务按等级开放** | 村庄：维修/市场/任务/换船；乡镇：+船厂+酒馆；城市：+交易所+声望 |
| 2 | **母港成长线** | 渔港村落 → 乡镇（5,000 金 + 100 木 + 50 铁）→ 港口城市（30,000 金 + 400 木 + 200 铁）；升级后解锁对应面板 |
| 3 | **岛屿港口 UI 统一** | 岛屿港口与母港共用面板组件，避免两套 UI 逻辑 |
| 4 | **特产价格差异化** | 不同等级港口特产价格不同（大港便宜、小港贵），形成贸易路线 |

### 3.2 验收标准

- 村庄级港口看不到「船厂」「酒馆」入口
- 母港升级到乡镇后，船厂与基地建设面板出现在母港
- 母港升级到城市后，交易所与声望面板出现
- 同一特产在城/镇/村三个港口价格呈梯度（差异 ≥ 15%）

### 3.3 不做

- 不做 Boss 技能
- 不做美术资源替换（走独立排期）
- 不做多存档界面重构

## 6. 材料与生产链体系（历史设计存档）

### 4.1 四大类与明细

| 大类 | 明细材料 |
|---|---|
| **食物** | 小麦、大米、土豆、甘蔗、鱼类、肉类、水果 |
| **原材料** | 木材、石材、铁矿、铜矿、硝石、粘土、棉花、亚麻 |
| **消费品** | 布料、陶器、工具、啤酒、朗姆酒、香料 |
| **消费品·军用品** | 火枪、火炮、弹药 |
| **贵金属** | 银锭、金锭、宝石 |

> 军用品归入消费品大类，单列子类：它们由原材料加工而来，属于**产成品**。

### 4.2 生产链（配方）

| 产成品 | 输入材料 | 设施 |
|---|---|---|
| 布料 | 棉花 ×2 | 工坊 |
| 陶器 | 粘土 ×2 | 工坊 |
| 工具 | 铁矿 ×2 + 木材 ×1 | 工坊 |
| 啤酒 | 小麦 ×3 | 工坊 |
| 朗姆酒 | 甘蔗 ×3 | 工坊 |
| **火枪** | 铁矿 ×2 + 木材 ×2 | 工坊（军械） |
| **火炮** | 铁矿 ×3 + 铜矿 ×2 | 工坊（军械） |
| **弹药** | 铁矿 ×1 + 硝石 ×1 | 工坊（军械） |

食物与原材料由农场 / 矿场直接产出，无需配方。

### 4.3 替代与互补关系（交叉弹性的计算依据）

| 关系类型 | 符号 | 例子 | 传导逻辑 |
|---|---|---|---|
| **替代品** | 正 | 啤酒 ↔ 朗姆酒 | A 涨价 → 需求转向 B → B 涨价 |
| **投入品** | 正 | 小麦 → 啤酒 | 原料涨价 → 成本上升 → 成品涨价 |
| **互补品** | 负 | 火炮 ↔ 弹药 | 弹药贵 → 用炮成本高 → 火炮需求降 |

**关系的来源**：投入品关系由 4.2 的配方表**自动生成**，替代与互补关系手工登记。
这样交叉弹性不再依赖拍脑袋的系数，而是有生产链与消费结构作依据。

### 4.3.1 市场界面分类分页（参考《维多利亚 3》）

《维多利亚 3》的商品页按 **Staple / Luxury / Industrial / Military** 四大类组织，
本作对应关系：

| 本作分类 | 对应《维多利亚 3》 | 说明 |
|---|---|---|
| 食物 | Staple goods | 日常必需品 |
| 原材料 | Industrial goods | 用于加工 |
| 消费品 | Luxury goods | 加工后的高价品 |
| 军用品 | Military goods | 军械类 |
| 贵金属 | Prestige goods | 高价值 |

**界面方案**

    市场行情
    [食物] [原材料] [消费品] [军用品] [贵金属] [全部]

| 项 | 规则 |
|---|---|
| 默认页签 | **食物** |
| 页签布局 | 全屏，与现有市场面板一致 |
| 行内容 | 商品 / 买价 / 卖价 / 周涨跌 / 库存 / 船上 / 仓库 / 交易 |

> 取值方式借鉴其「分类浏览 + 供需状态」的组织方式，不复制其数值模型。

### 6.6 航行结构：邻接图而非等级跳转（2026-11-18 决定）

| 项 | 决策 |
|---|---|
| 现状 | 9 图线性蛇形链（1→2→…） |
| 1.3.2 方案 | 改为**邻接图**：每张图显式声明邻居，通行按邻接判定 |
| 等级的作用 | 只表示难度与解锁门槛，**不再是通行规则** |
| 同级任选如何实现 | 同级三张图互相邻接（三角），并与相邻级别的三张图互通，自然形成「同级任选」 |
| 为什么这样做 | 为未来的世界地图保留兼容性：世界地图只需渲染同一张邻接图 |

**邻接设计**

| 关系 | 连接 |
|---|---|
| 同级内 | 三张图两两相邻（3 条边） |
| 相邻级别 | 本级三张 ↔ 上级三张（9 条边） |
| 母港 | 连接 1 级三张图 |

**通行规则**

| 项 | 规则 |
|---|---|
| 入口 | 目标图必须与当前图相邻 |
| 解锁 | 目标图级别 ≤ 已通关最高级别 + 1 |
| Boss 门禁 | 跨级前进仍需击败当前级 Boss（保留原规则） |
