# 美术资源开发设计

> 美术是本项目未来最大的一块增量工作。本文档定义**总体策略**与**详细规范**，
> 后续按此拆分成具体生成任务。

## 1. 现状与目标

| 项 | 现状 | 目标 |
|---|---|---|
| 船舶 | 程序化几何（矩形+三角） | 手绘感 2D 俯视帆船，10 级 ×3 变体 |
| 海面 | 纯色 + 网格线 | 可平铺的海面纹理 + 浪花 |
| 岛屿 | 同心圆 | 有海岸线、植被、码头的手绘岛屿 |
| 港口/母港 | 空白陆地 + 文字按钮 | 港口场景插画 + 建筑立面 |
| UI | 纯色面板 + 系统字体 | 羊皮纸/黄铜边框的低多边形 UI 套件 |
| 图标 | 无 | 商品、火炮、装备、船员、状态全套图标 |

**风格基调**：17~18 世纪加勒比，写实偏厚涂，暖色调，低饱和；UI 用羊皮纸 + 黄铜 + 深蓝木纹。
参考：大航海时代 IV / 席德梅尔的海盗。

## 2. 生产工具链（三条通路）

### 2.1 本地 ComfyUI（主力）

- 环境：本机已部署 ComfyUI，通过 **dsh-comfyui 插件**调用
- 优势：免费、可批量、可控性高（ControlNet / img2img）
- 适用：船只、岛屿、海面纹理、UI 边框、图标

调用方式：先用 `comfyui_workflow list` 找可用工作流，再 `comfyui_workflow run` 执行，
参数（尺寸、提示词、步数）通过 run 的覆盖参数传入。

### 2.2 Godot 内置美术能力（补充）

- 适用：**程序化生成**的重复元素（浪花、粒子、光效）、占位图、图标描边
- 手段：`GradientTexture`、`NoiseTexture`、`Line2D`、着色器
- 优势：零外部依赖、可随参数变化（换颜色不用重出图）

### 2.3 阿里百炼 · Qwen 图像模型（线上补充）

- 通过 DSH 已接入的百炼 token plan 调用 Qwen 图像模型
- 优势：**概念设计**阶段出参考图快，适合先定风格再交给 ComfyUI 批量
- 注意：线上模型结果不可完全复现，**只用于概念探索**，最终素材以本地生成为准

### 2.4 三条通路的分工

```
概念探索        → Qwen（快、随机、出方向）
风格定稿        → ComfyUI + ControlNet（可控、可迭代）
批量生产        → ComfyUI（LoRA + 固定 seed + 批量队列）
程序化/变体     → Godot 内置（着色器改色、粒子、边框九宫格）
```

## 3. 资产规格规范

| 资产类型 | 尺寸 | 格式 | 备注 |
|---|---|---|---|
| 船只（俯视） | 256×256 / 512×512 | PNG 带透明 | 朝上（0°），代码里旋转 |
| 岛屿 | 512×512 | PNG 带透明 | 边缘留 8% 透明安全区 |
| 海面平铺纹理 | 512×512 | PNG 无缝 | 需 tileable |
| 港口背景 | 1600×900 | JPG | 放到 base 场景做插画背景 |
| UI 面板 | 九宫格切图 | PNG | 边框 32px 可拉伸 |
| 图标 | 64×64 | PNG | 统一描边 2px |
| 头像（船员） | 128×128 | PNG | 圆形裁切 |

**统一要求**：sRGB、无预乘 alpha、命名 `类型_标识_变体.png`（如 `ship_brig_navy.png`）。

## 4. 提示词模板（ComfyUI / Qwen 通用）

```
正向：
top-down view, 18th century sailing ship, {船型}, {帆色}, hand-painted,
warm sunlight, high detail, game asset, transparent background, centered,
no text, no watermark

负向：
text, watermark, logo, blurry, low contrast, 3d render, photorealistic,
modern elements, multiple ships
```

**关键约束**：
- 必须写 `top-down view`（否则出侧视）
- 必须写 `centered` + `transparent background`（方便抠图）
- 船体朝向统一**朝上**，运行时用 `draw` 旋转

## 5. 与代码的衔接

现有渲染是 `_draw()` 纯程序化。替换方案：

| 阶段 | 做法 |
|---|---|
| 1 | 保留程序化绘制作为**回退**：没有贴图时仍能跑 |
| 2 | 引入 `Sprite2D` + `Texture2D`，通过 `ShipDef.sprite_path` 字段指定 |
| 3 | 数据表加字段后，美术只需改 `.tres` 就能换图，**不动代码** |

**数据契约**（预留字段）：

```
ShipDef:  sprite_sail, sprite_hull
IslandDef: sprite_base       # 岛屿贴图
GearDef:  icon
CrewDef:  portrait
CommodityDef: icon
```

## 6. 排产顺序

| 批次 | 内容 | 依赖 |
|---|---|---|
| 1 | 船（10 级 ×3 变体 = 30 张）+ 岛屿 3 级 | 无 |
| 2 | 海面纹理、浪花、港口背景 | 批次 1 |
| 3 | UI 九宫格套件（面板/按钮/滚动条） | 无 |
| 4 | 图标（商品 4 / 火炮 10 / 装备 20） | 批次 3 |
| 5 | 船员头像（按稀有度分色框） | 批次 3 |

## 7. 验收标准

- 缩小到 50% 仍能分辨船型与阵营
- 同屏 20 艘船时，贴图内存 < 64MB
- 所有贴图有 @2x，在 Retina 上不糊
- 无贴图时游戏仍可运行（回退到程序化绘制）

## 8. 暂不做

- 骨骼动画 / 逐帧动画（先用旋转 + 轻微起伏模拟）
- 3D 模型
- 动态天气贴图
